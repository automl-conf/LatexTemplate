Designing neural networks for deployment on resource-constrained devices involves the dual challenge of selecting architectures that perform well on a given task while respecting hardware constraints.
Hardware-aware Neural Architecture Search (HW-NAS) addresses this challenge by automating architecture design under hardware supervision, offering an automated alternative to the otherwise-manual tuning of the architecture for a given deployment scenario. However, most HW-NAS methods are tailored to a single target deployment scenario, requiring re-searching the architecture when the deployment scenario---in this work, the device used to run the network---changes.

In this work, we address such a limitation focusing on multi-device HW-NAS. In this, our goal is to discover architectures performing well on \emph{(i)} task-specific metrics---in this work, validation accuracy---\emph{(ii)} hardware-efficiency metrics---in this work, post-compilation latency---across \emph{multiple devices}.
Current HW-NAS approaches to jointly tackle \emph{(i-ii)} typically rely on real-world performance measurements collected for a fixed target device, which are typically very expensive to collect as they require to compile a large number of networks. 
Furthermore, current approaches to ensure cross-device performance rely on \emph{(i)} strong assumptions circa analytical approximations of downstream hardware efficiency or \emph{(ii)} predictors approximating real-world measurements. Clearly, \emph{(i-ii)} do hinder practical applicability in risk-averse scenarios, as \emph{(i)} assumptions risk being too coarse for practical use cases and \emph{(ii)} predictions' uncertainty is difficult to bound.

In this work, we propose a two-stage approach to HW-NAS. Initially, our controller meta-learns to optimize architectures under computational constraints on fictional synthetic devices. Then, we deploy the controller on a target---unseen---real-world device, where it is tasked with optimizing the architectures by directly using real-world measurements. Critically, meta-learning the optimization process drastically limits the number of networks deployed, making real-world measurements a valid alternative when probing \textit{the right networks}. In particular, we train our controller exposing it to a diverse range of synthetic hardware devices. With this, we simulate structured environments enabling the controller to learn policies for device-conditioned architecture selection, encouraging the emergence of a device-adaptive behavior.

By training on these synthetic devices, the controller acquires a model of how latency patterns vary across devices. When deployed in a real hardware scenario, this policy can transfer its prior knowledge to explore more effectively under the unknown target latency distribution. This allows us to abandon amortized estimation of latency values---obtained through coarse approximations or the use of predictors---and directly compile and measure real-world latency values on a handful of candidate networks.

To transfer solutions across devices, we leverage recent advancements on Reinforcement Learning (RL), which we complement with accuracy proxies in the reward function to reduce the associated computational burden. In particular, we limit the cost of using RL in the meta-learning phase by training multiple controllers using NASWOT, a popular training-free proxy for downstream classification accuracy that does not require training. Such a training-free accuracy proxy is especially suitable in our setting because they are fast to compute and data-agnostic.

In summary, our work makes the following key contribution: we develop a \textbf{randomized RL training procedure for HW-NAS}, crafting a controller which generalizes across diverse deployment devices at test time. This allows us to bypass inaccurate and expensive ways to estimate post-compilation latency, and rather \textbf{use a very limited number of real-world measurements} at test time.
